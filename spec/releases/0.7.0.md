# Dashhaus 0.7.0

Status: written in its release PR, at the commit whose files [0.7.0.sha256](0.7.0.sha256) records. It
shipped when [v0.7.0](https://github.com/Krystosterone/dashhaus/releases/tag/v0.7.0) exists.

## Release page

Guest Wi-Fi's New password now asks before replacing the old one, since every device already connected loses the old
code; making a new code still takes one press. Building a skin: core no longer exports `batterySaid`, `alertSentence`,
`vacuumWarningSentence` or `leftOpenSentence` (say them with `batteryAdvice`, `alertSaid`, `vacuumWarningSaid` and
`leftOpenText`), and `GUEST_WIFI_ACTIONS` now marks New password with `when`, which a skin that reads it should apply.

## What changed since 0.6.0

### Breaking changes

- `@dashhaus/core/entities` and its words subpaths (`battery`, `binarySensor/words`, `cover/words`, `vacuum/words`) no longer export `batterySaid`, `alertSentence`, `vacuumWarningSentence` or `leftOpenSentence`: say a warning with `batteryAdvice`, `alertSaid`, `vacuumWarningSaid` and `leftOpenText` and put the card's name before it.
- `GUEST_WIFI_ACTIONS` now says guest Wi-Fi's New password asks first when `access` is `password`, so a card built from it asks before making one. A skin that reads `GUEST_WIFI_ACTIONS` should apply `when`, so a code still gets made in one press.

### New

- Core exports `lockCodeFor` (`@dashhaus/core/entities/lock/words`), `alarmCodeFor` (`@dashhaus/core/entities/alarm/words`) and `codeFor` (`@dashhaus/core/entities/guard`), the verb phrase a keypad asks a code for: a lock's or an alarm's own, or a generated card's from its action.

Internal changes, left out: 8.

## API changes since 0.6.0

Read from the packed type declarations (`npm run release:api`). A removed entry or export, or a changed
declaration, is breaking unless it is members added to an interface the package hands out and never takes in.

Of the 183 changed declarations, all but seven differ only in React 19's type spelling: `JSX.Element` is imported from
`react` instead of `react/jsx-runtime`. The rest are `GUEST_WIFI_ACTIONS` (its `when`, owned by the breaking note
above), four primitives and `RowLayout` (a ref's `current` typed `T | null`, which is what React 18's `RefObject<T>`
already reads), and `DYSON_SEEDS` (a `heatingWarning` seed). None changes a call or the supported React range
(`^18.3.1 || ^19.0.0`).
