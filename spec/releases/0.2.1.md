# Dashhaus 0.2.1

Status: written in its release PR, at the commit whose files [0.2.1.sha256](0.2.1.sha256) records. It shipped when
[v0.2.1](https://github.com/Krystosterone/dashhaus/releases/tag/v0.2.1) exists. The first release the Release workflow
ships on its own (spec/release.md → Releasing); this record was started by hand and finished in its release PR.

A patch release of all seven packages, which share the fixed version (`spec/release.md` → Versioning). It changes two
things a consumer sees: a skin scaffolded by `create-dashhaus-skin` now builds to exactly one file, and every package
carries an npm provenance attestation.

## Release page

A patch release. A skin made with `npm create dashhaus-skin` now builds to exactly one file, without the empty
`style.css` and the CSS warnings beside it. Every package is now published from this repository's GitHub Actions, with
an npm provenance attestation naming the commit it was built from.

## What changed since 0.2.0

- **The scaffold builds one file again** ([#60](https://github.com/Krystosterone/dashhaus/issues/60)). Every skin
  from `npm create dashhaus-skin` wrote an empty `dist/style.css` beside `dist/dashhaus-<skin>.js` and printed
  `[css-syntax-error]` warnings on every build, on any Vite 5 the template allows. The template's
  `stylesInShadowRoot` plugin gave a component's empty stylesheet module an id ending in `.css`, so Vite's CSS
  pipeline parsed `export {};` as CSS and wrote it out. Its id now ends in `.js`. The bundle and its CSS are
  unchanged; only the stray file and the warnings go.
- **Every package carries npm provenance.** Every package is now published from this repository's GitHub Actions,
  with an npm provenance attestation naming the commit it was built from, and the bundle's console line names its
  version instead of a commit. The installed packages behave as before.
- **The author journey checks every file.** `verify/dx/author.js` counted only `.js` files in `dist/`, which is how the
  stray stylesheet passed. It now asserts the whole folder is the one bundle, and that the build prints no CSS
  warnings. Against the published `0.2.0` tarballs it fails at the build; against these it passes.
- **Version:** all seven public manifests and their internal ranges move from `0.2.0` to `0.2.1`, the scaffolder
  template's included.

### Upgrading

Nothing to change in a deploy-only app or a developer's app: update the packages together. A skin scaffolded from
`0.2.0` keeps writing the empty stylesheet until its own `vite.config.js` gets the same one-line fix: in
`stylesInShadowRoot`'s `resolveId`, return `` `\0dashhaus-style:${resolved.id}.js` `` instead of
`` `\0dashhaus-style:${resolved.id}` ``. The stray file was never deployed, so leaving it is harmless.
