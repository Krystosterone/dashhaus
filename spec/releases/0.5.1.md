# Dashhaus 0.5.1

Status: written in its release PR, at the commit whose files [0.5.1.sha256](0.5.1.sha256) records. It
shipped when [v0.5.1](https://github.com/Krystosterone/dashhaus/releases/tag/v0.5.1) exists.

## Release page

Inside Home Assistant, a media player's details now end with Open in Home Assistant, which opens Home Assistant's own
player for what the card leaves to it, such as browsing media and grouping speakers. A guest Wi-Fi join QR code that
fails to load no longer shows a broken picture, and Field's compact rows and Orb's glow budget got a set of small fixes.
There is nothing to change when you upgrade.

## What changed since 0.5.0

### New

- Inside Home Assistant, the media player's details end with Open in Home Assistant, which opens Home Assistant's own player for what the card leaves to it, such as browsing media and grouping speakers: a raised pill last in Orb's sheet, a wide Open key under a Home Assistant legend last in Field's panel, and nothing where there is no host to open it, as in a standalone app. `HaMediaPlayerTile` and `HaMediaPlayerModule` wire it with `useHaMoreInfo`, `MediaPlayerTile`, `MediaPlayerCard` and `MediaPlayerModule` take it as `onOpenMore`, and `@dashhaus/core/entities/mediaPlayer/words` adds its words, `OPEN_IN_HOME_ASSISTANT` and `openInHomeAssistantSaid`.

### Fixed

- A guest Wi-Fi join QR code that fails to load no longer shows the browser's broken picture in Orb or Field: its frame stays empty and how to join starts with "No QR code." (core's new NO_QR and qrFailedWords).
- Field's calendar row on a 12-hour dashboard says another day's event as "9:30 AM Tomorrow · School trip", so even the narrowest row keeps the AM or PM in sight.
- Field's compact cover row for a garage door or gate with no position says Opening or Closing on its line while it moves, instead of only blank segments.
- Field's compact rows between 300 and 340 px wide no longer cut a warning's word: a row whose line carries a warning takes the narrow screen, and the weather row says "3 warnings" where its most urgent one won't fit.
- Orb's glow budget: a compact card's hidden glow no longer halves the next card's, and an open details sheet always glows full, wherever its tile sits.
- Orb's guest Wi-Fi details no longer jump when the note under Refresh and New password says it is waiting.
- The demo house transport answers each entity's history from the demo that owns it, so its numeric, energy and sensor cards show their own day rather than one generic morning.

Internal changes, left out: 2.

## API changes since 0.5.0

Read from the packed type declarations (`npm run release:api`). A removed entry or export, or a changed
declaration, is breaking until a person says otherwise.

- **Changed** `GUEST_WIFI_SEEDS` in `@dashhaus/core/seeds/guestWifi`
- **Changed** `MediaPlayerCard` in `@dashhaus/orb`
- **Changed** `MediaPlayerCardProps` in `@dashhaus/orb`
- **Changed** `HaMediaPlayerTileProps` in `@dashhaus/orb`
- **Changed** `MediaPlayerModule` in `@dashhaus/field`
- **Changed** `MediaPlayerModuleProps` in `@dashhaus/field`

None of these break a consumer: `MediaPlayerCard`, `MediaPlayerModule` and their props add an optional `onOpenMore`
(and `HaMediaPlayerTileProps` stops exposing it because the connected tile supplies it), and `GUEST_WIFI_SEEDS` gains a
`qrFails` seed, which only widens `GuestWifiSeedName`. Code compiled against 0.5.0 keeps compiling.
