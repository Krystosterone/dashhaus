# Dashhaus 0.3.0

Status: written in its release PR, at the commit whose files [0.3.0.sha256](0.3.0.sha256) records. It
shipped when [v0.3.0](https://github.com/Krystosterone/dashhaus/releases/tag/v0.3.0) exists.

## Release page

One breaking change for Orb YAML: cards no longer take a `color` of their own, so delete `color` from your cards and
set the dashboard's `accent` instead. New in Orb and Field: a guest Wi-Fi card with the network's name, its code and a
join QR code. Lights and covers Home Assistant reports as unknown, such as RF blinds, now say Unknown and can be driven.

## What changed since 0.2.1

### Breaking changes

- `@dashhaus/core`'s toggle no longer carries a colour: `color` is gone from `useHaToggle`'s options, `toggleFromHass`'s options and the toggle model, and `@dashhaus/core/entities/color` (its `ColorName` type) is removed. Stop passing `color` to `useHaToggle` or `HaToggleTile`.
- `LightEntity` and `CoverEntity` in `@dashhaus/core` have a new `unknown` state, for a light or cover that can be driven but hasn't said where it is, and their actions now run in it: handle `unknown` wherever your code switches on `state`.
- Orb's cards no longer take a colour of their own: the `color` YAML key and the cards' `color` prop are gone (with `COLORS`, `ColorProp`, `SlotColor` and `ColorName` from `@dashhaus/orb`), and every orb is on in the accent. Delete `color` from your Orb YAML, and set the dashboard's `accent` to change the one colour every card shares.

### New

- A guest Wi-Fi card in Orb and Field: the guest network's name, what a guest types to use it, and the network's join QR code, with Refresh and New code in its details. Lovelace picks it for any UniFi Hotspot Manager `sensor.*_voucher`; with `card: guestWifi` it also shows a Wi-Fi password kept in an `input_text`, `text` or `sensor`, its actions a `button`, `input_button` or `script`, and New password asks first.
- A new skin's AGENTS.md has an Install by hand section: an agent that can't reach Home Assistant, such as one in the browser, hands over the built file and walks the person through File editor, Resources and a new dashboard, with no token or SSH.
- A new skin's npm run snapshot can use a Chromium or Chrome already on your machine: set DASHHAUS_CHROMIUM to its path.
- A new skin's npm test fails on a var(--<skin>-…) that no token defines, such as one left behind when a token is renamed.
- @dashhaus/core/testing works with Vitest 4 and 5 as well as 3: the package accepts any of them as its Vitest peer.
- @dashhaus/core's entity fields, hook options and action handlers carry doc comments in your editor: the Home Assistant service each action calls and what it reports when refused.
- @dashhaus/dashboard/schema exports PAGE_KEYS, ROW_KEYS and LOVELACE_KEYS: the keys a page and a row take and the ones Home Assistant reads itself, for a skin that lists its own YAML keys.

### Fixed

- A new skin's AGENTS.md names every label, format and history helper an agent can import from @dashhaus/core/entities, and says a card's stories file needs no Storybook.
- A new skin's AGENTS.md says which @dashhaus/core module each weather helper is in, that the card frame's props must stay for npm run add's later cards, and what happens to a web font with no network.
- A new skin's dashboard keeps its Home header when deployed, as its preview shows it.
- A new skin's npm run snapshot draws a docked nav at the foot of a full-page snapshot instead of mid-page, and says when a web font failed to load.
- Field's light and fan modules draw no fader thumb while off, since Home Assistant reports no level then, instead of one at full or at the first speed; a tap or a slide still turns them on there.
- Lights and covers Home Assistant reports as unknown, such as RF blinds, garage doors with no sensor and light groups before their first state, can be driven from Orb and Field, and say Unknown instead of Unavailable.
- npm run add -- lock now shows a lock on a new skin's preview, as it says: @dashhaus/core's demo house includes the front and back door locks.
- Orb's fan card and Field's fan module tell a screen reader the speed control is Off while the fan is off, instead of a speed it was never reported at.
- Orb's light card keeps its brightness bar while the light is off, as Home Assistant reports it, instead of swapping it for an On/Off pill; sliding it turns the light on.

Internal changes, left out: 4.

## Live Home Assistant smoke

tarballs `npm run release:pack` packed there — all eight files match [0.3.0.sha256](0.3.0.sha256) — each journey in
a fresh app installing only those tarballs. It was a first creation: before deploying, the instance had no `home-orb`,
`home-field` or `dashhaus-my-skin` dashboard and no Dashhaus resource. The screenshots and console excerpts stayed with
the operator (each dashboard and an open details, the reloaded Orb, the pressed control, the Resources list filtered
to `dashhaus`, and each raw configuration editor); everything the smoke created was removed afterwards.
