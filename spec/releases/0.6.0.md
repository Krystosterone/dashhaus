# Dashhaus 0.6.0

Status: written in its release PR, at the commit whose files [0.6.0.sha256](0.6.0.sha256) records. It
shipped when [v0.6.0](https://github.com/Krystosterone/dashhaus/releases/tag/v0.6.0) exists.

## Release page

Orb's and Field's wall layout now puts its rooms in Home Assistant's own area order, each floor's in turn, instead of
by name, so reordering areas under Settings → Areas, labels & zones moves the wall's columns; drag them into that
order there to keep the wall as it was. `areaOrder` is there for your own layouts, Field's modules print Today's
summary short enough for a narrow module, and a slider's assistive swipe moves one step from where it is. The
documentation site's home-page link points at Storybook again.

## What changed since 0.5.1

### Breaking changes

- Orb's and Field's wall layout (`layout: wall`) puts its rooms in the order Home Assistant keeps your areas in, each floor's in turn, instead of by name, so reordering areas under Settings → Areas, labels & zones moves the wall's columns. Home Assistant keeps areas you never reordered in the order you made them: to keep the wall by name, drag them into that order there.

### New

- `areaOrder` in `@dashhaus/core/lovelace/layout` reads Home Assistant's area order, each floor's areas in turn, and `wallAreas` takes it as its `order`; `autoInput` hands on `hass.floors` and each area's floor for it, and `@dashhaus/core/demo` adds `DEMO_WALL_HOUSE_ORDERED`, the worst-case wall house with its rooms put in order.
- Field's modules print Today's summary without its closing "today" ("Not detected"), so it fits whole on a narrow module; the panel and the spoken label keep it whole. `shortTodaySummary` in `@dashhaus/core/entities/today` gives the short form.

### Fixed

- A slider's assistive swipe (a player's seek, a colour temperature whose ends don't divide by its step) moves it one step from where it is, as an arrow key does, instead of by an amount the browser picks.
- The documentation site's home page sends its kinds list to Storybook, where both skins' cards are, instead of to the removed /skins/ page.

Internal changes, left out: 1.

## API changes since 0.5.1

Read from the packed type declarations (`npm run release:api`). A removed entry or export, or a changed
declaration, is breaking until a person says otherwise.

- **Changed** `useRangeSlider` in `@dashhaus/core/primitives`
- **Changed** `useSlider` in `@dashhaus/core/primitives`
- **Changed** `LovelaceHass` in `@dashhaus/core/lovelace`
- **Changed** `autoInput` in `@dashhaus/core/lovelace`
- **Changed** `autoInput` in `@dashhaus/core/lovelace/skin`
- **Changed** `LovelaceHass` in `@dashhaus/core/lovelace/skin`
- **Changed** `wallAreas` in `@dashhaus/core/lovelace/layout`
- **Changed** `AutoInput` in `@dashhaus/core/lovelace/layout`
- **Changed** `AutoInput` in `@dashhaus/orb/lovelace/auto`
- Added `shortTodaySummary` to `@dashhaus/core/entities`
- Added `shortTodaySummary` to `@dashhaus/core/entities/index`
- Added `shortTodaySummary` to `@dashhaus/core/entities/today`
- Added `DEMO_WALL_HOUSE_ORDERED` to `@dashhaus/core/demo`
- Added `areaOrder` to `@dashhaus/core/lovelace/layout`

None of these break a consumer by declaration. `useSlider` and `useRangeSlider` hand back their hidden input's props
with `step` narrowed to a number, which still spreads onto an `<input>`; `LovelaceHass`, `AutoInput` and `wallAreas`
gain optional fields (`floors`, an area's `floor_id`, `order`); and `areaOrder`, `shortTodaySummary` and
`DEMO_WALL_HOUSE_ORDERED` are new. The breaking note is the wall layout's column order, which changes what the same
YAML draws once Home Assistant reports ordered areas.
