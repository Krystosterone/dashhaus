`@dashhaus/core/primitives` holds the behaviour every skin's controls share, without markup or styles. Each is a hook
whose result you spread onto your own elements. Orb's round button and Field's key are both `usePress`; both skins'
brightness tracks are `useSlider`.

The feel of a primitive depends on its skin's CSS as much as its code: a track's scroll-or-set on touch needs
`touch-action: pan-y`, a press needs its `:active` style. Try them on a phone in any card's story in
[Storybook](/dashhaus/storybook/).

## usePress

A button: a tap, an optional press and hold, an optional latch, and an unavailable state. The click that ends a hold
doesn't also press. An unavailable control stays focusable and says so with `aria-disabled`; a disabled one is out of
reach. A plain one-shot button doesn't need it: use a `<button>`.

## useSlider and useRangeSlider

A horizontal track. Pointer input goes to a hit layer you draw over the track: a mouse sets the value on press, a
touch only on a tap or once the finger moves sideways, so scrolling the page past a slider never changes it. A hidden
native range input carries the keyboard and the screen reader, with the value text you give. `useRangeSlider` is the
same with two thumbs, a low and a high, as for a heat and cool range.

## useSheet

A native modal `<dialog>` for details: it mounts and shows, locks the page's scroll, holds a `data-closing` attribute
while your exit transition runs, closes on Escape and on the backdrop, and on a phone drags down to close from its
header. Orb's details sheet and Field's detail panel are both on it.

## useKeypad

A code keypad for an alarm: the code typed so far, digits, delete and enter from its keys or a physical keyboard, and
the answer. It is busy until `onSubmit` answers; a wrong code (`false`) is cleared for another try, and a failed call
(a throw) keeps the code so Enter tries again. That is the shape of an alarm hook's `onArm` and `onDisarm`.

A text code (`text: true`, for a `codeFormat` of `text`) can't be typed on digit keys, and a phone or wall panel has
no physical keyboard. For one, the hook also returns `inputProps`: spread them onto an `<input>` and it becomes the
field the code is typed into. It takes the focus in the keypad's place, so a touch screen brings up its own keyboard,
and Enter in it submits; your digit keys still type into the same code.
