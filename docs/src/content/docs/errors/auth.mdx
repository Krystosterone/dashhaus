The packages never log in. They have no login form, store no token and refresh none: whoever opens the connection owns
it, and hands the store a transport.

## In Home Assistant

A skin's Lovelace card uses the frontend's own authenticated connection. The bundle carries no credentials, and the
card never closes the frontend's connection. Nothing to set up.

## In an app of your own

Get an `Auth` from `home-assistant-js-websocket`, through Home Assistant's OAuth flow (`getAuth`) or a long-lived token
your app manages, and open the connection with `connectHomeAssistant`:

`createHomeAssistantTransport` wraps a `Connection` you already have. The transport is yours: call
`transport.close()` when you're done. `HaProvider` connects and disconnects the store, but never closes the transport.
`@dashhaus/core/websocket` is the only module that imports `home-assistant-js-websocket`.

## On a kiosk or a wall panel

Keep Home Assistant's credentials off the browser: run a small gateway on a server you trust, and give the page a
transport that talks to it. The gateway is where security lives, so it should allowlist the entities, services and
service fields the panel may use, refuse anything else, strip credentials and alarm codes from what it passes on,
cap the size and rate of requests, and never log tokens.
