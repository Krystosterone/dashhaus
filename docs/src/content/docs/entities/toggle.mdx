## Component

`<HaToggle>` is `useHaToggle` as a component that draws nothing of its own. It takes every option of the hook as a
prop, and hands the hook's result to its child function. Use it where hooks can't go, such as one per item of a list.

## Hook

<ApiSignature from="@dashhaus/core" name="useHaToggle" />

It reads the entity, its area and today's history. `icon`, `color` and `description` are yours to give: Home Assistant has no such attributes for a mode.

## Every mode

Hooks can't be called in a loop, so a list renders one headless component per entity. The selector returns a string: `useHaSelector` re-renders only when its value changes, and a string of ids changes only when an entity comes or goes. Lists skip each item's history read with `loadHistory={false}`.

## Tasks

### On for an hour

<Example file="entities/toggle/OnFor.tsx" />

There is no `onTurnOnFor` in the actions on purpose: Home Assistant can't turn an `input_boolean` or a `switch` on for a while, so the timer belongs to whoever runs it. Orb's tile and Field's module take your `durations` and `onTurnOnFor` and draw the choices. A timer in Home Assistant itself, an automation or a `timer` helper, outlives the page; this one doesn't.
