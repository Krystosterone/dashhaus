The home's outdoor conditions from one `weather.*` entity, with an air-quality sensor, `sun.sun` for day and night, and the hourly and daily forecasts. Read-only.

## Quick example

<Example file="entities/weather/Outside.tsx" />

`aqi` is only read with `aqiScale: "US"` and a sensor whose `device_class` is `aqi`: the hook won't band a figure on a scale it can't name. `isDay` comes from the sun entity you give; without one it stays unknown rather than guessing day.

## Component

`<HaWeather>` is `useHaWeather` as a component that draws nothing of its own. It takes every option of the hook as a
prop, and hands the hook's result to its child function. Use it where hooks can't go, such as one per item of a list.

<ApiMembers from="@dashhaus/core" name="HaWeather" only={["entityId", "children"]} />

## Hook

It reads the weather entity, its companions, today's temperature history, and the forecasts through `weather.get_forecasts`.

### Returns

`hourly` and `daily` are `undefined` until the first forecast read settles. They are read once an hour, and the previous hour's forecast stays up while the next loads. Pass `loadForecasts={false}` when another part of your app reads them.

## Every weather entity

Hooks can't be called in a loop, so a list renders one headless component per entity. The selector returns a string: `useHaSelector` re-renders only when its value changes, and a string of ids changes only when an entity comes or goes. Lists skip each item's history read with `loadHistory={false}`.
