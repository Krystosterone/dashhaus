One `alarm_control_panel.*` entity: its state, the modes it arms to, whether it wants a code, and its exit and entry delays.

## Quick example

<Example file="entities/alarm/ArmAway.tsx" />

Arming and disarming answer, unlike the other actions: `true` when Home Assistant took the call, `false` for a wrong code, and a rejection when the call didn't go through. The store never keeps a call with a code in it, so a failed disarm is never offered again with the code.

## Component

`<HaAlarm>` is `useHaAlarm` as a component that draws nothing of its own. It takes every option of the hook as a
prop, and hands the hook's result to its child function. Use it where hooks can't go, such as one per item of a list.

<ApiMembers from="./api-types" name="HaAlarmProps" only={["entityId", "children"]} />

## Hook

<ApiSignature from="@dashhaus/core" name="useHaAlarm" />

It reads the panel, its area and today's history. Home Assistant's alarm entity has no delay length, so `exitDelay` and `entryDelay` give it (Alarmo's `delay` attribute wins when it reports one). `openSensors` and `triggeredBy` are yours to compose from your door and window sensors.

#### `actions`: AlarmHandlers

<ApiMembers from="@dashhaus/core" name="AlarmHandlers" notes={{"onArm": "Calls `alarm_control_panel.alarm_arm_<mode>` (`home`, `away`, `night`, `vacation`, `custom_bypass`) with the code when given. A failure other than a wrong code also goes to `onActionError` before the promise rejects.

## Every alarm panel

Hooks can't be called in a loop, so a list renders one headless component per entity. The selector returns a string: `useHaSelector` re-renders only when its value changes, and a string of ids changes only when an entity comes or goes. Lists skip each item's history read with `loadHistory={false}`.
