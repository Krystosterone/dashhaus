Put Dashhaus in a React app of yours: install the packages, connect the store, then draw one light twice. The first
uses your own markup on the headless hook; the second, a skin's ready-made component. `@dashhaus/core` on its own is
enough for the first: no skin, no generator and no Lovelace card come with it. If you only want a finished
dashboard in Home Assistant, [Install from the Marketplace](/dashhaus/start/install/) needs no React at all.

<Aside type="caution" title="Dashhaus is in beta">
  A new `0.x` version (0.2 to 0.3) may change a hook or a type you use. A caret range keeps you on one `0.x` line,
  every `@dashhaus/` package shares one version, and each release says what to change. [More](/dashhaus/intro/#beta).
</Aside>

## 1. Install

<Tabs syncKey="way">
  <TabItem label="Headless">
    ```sh
    npm install @dashhaus/core react react-dom home-assistant-js-websocket
    ```

    `@dashhaus/core` has no markup and no CSS. React 18.3 or newer (19 included) is a peer.
    `home-assistant-js-websocket` is only needed by `@dashhaus/core/websocket`, which opens the connection.

  </TabItem>
  <TabItem label="Orb">
    ```sh
    npm install @dashhaus/orb @dashhaus/core react react-dom home-assistant-js-websocket
    ```

    `@dashhaus/orb` brings `@dashhaus/core` and `@dashhaus/dashboard` with it; naming core lets your own code import
    the store and the hooks. Importing `@dashhaus/orb` loads Orb's stylesheet, so build with a bundler that handles
    CSS imports, such as Vite.

  </TabItem>
  <TabItem label="Field">
    ```sh
    npm install @dashhaus/field @dashhaus/core react react-dom home-assistant-js-websocket
    ```

    The same as Orb: `@dashhaus/field` brings core and the dashboard package, and importing it loads Field's
    stylesheet.

  </TabItem>
</Tabs>

## 2. Put the store above your app

Everything reads Home Assistant through one store. `createHaStore` turns a transport into the store and `HaProvider`
connects it while it is mounted. Your app owns the login and the transport: here Home Assistant's OAuth flow from
`home-assistant-js-websocket`, then `connectHomeAssistant` from `@dashhaus/core/websocket`.

## 3. Draw a first control

<Tabs syncKey="way">
  <TabItem label="Headless">
    `useHaLight` hands over the light as a plain `LightEntity`, today's history, and its actions. You draw it:

    <Example file="start/LivingRoomLight.tsx" title="LivingRoomLight.tsx" />

    A tap calls `light.toggle`. When Home Assistant reports the new state, the store updates and the button follows:
    the hook never assumes the call worked.

  </TabItem>
  <TabItem label="Orb">
    `HaLightTile` is the same hook above Orb's light tile: the round button, the brightness track, the colour and
    warmth controls in its details sheet, and today's history.

    <Example file="start/LivingRoomLightTile.tsx" title="LivingRoomLightTile.tsx" />

    A tile fills the width of its container and keeps a fixed height, its footprint. Put `class="ha-surface"` on
    `<body>` for Orb's page background and type.

  </TabItem>
  <TabItem label="Field">
    `HaLightModule` is the same hook above Field's light module: a key, a fader and a screen, with a detail panel.

    <Example file="start/LivingRoomLightModule.tsx" title="LivingRoomLightModule.tsx" />

    Put `class="fd-surface"` on `<body>` for Field's page and type.

  </TabItem>
</Tabs>

Every kind of entity has a hook, a headless component and a tile and a module, so the same swap works for any of them.
[Entities](/dashhaus/entities/) lists them all.
