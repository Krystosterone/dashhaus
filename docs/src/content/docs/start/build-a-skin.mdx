A skin is a dashboard's whole look: its colours, type, cards and page. Dashhaus already reads your house: entities,
areas, services and history. A skin only draws it. You start from a working skin and change it, with an agent or
by hand.

<Aside type="caution" title="Not on npm yet">
  The packages are a `0.2.0` release candidate. Until they are published, use the release tarballs: put them in one
  folder and scaffold with `--tarballs`, as step 1 shows.
</Aside>

## Start

<Steps>

1. Create the project. Its folder name is the skin's name:

   ```sh
   npm create dashhaus-skin@latest my-skin
   # from release tarballs, in the folder that holds them:
   npx --yes --package ./create-dashhaus-skin-0.2.0.tgz create-dashhaus-skin my-skin --tarballs .
   ```

2. Install it and look at it:

   ```sh
   cd my-skin
   npm install
   npm run preview      # in the browser, on a sample house
   npm run snapshot     # or as PNGs in preview/snapshots/
   ```

   The preview draws the real Lovelace card, as Home Assistant will, on a sample house that includes an unavailable
   light, a sensor with no reading and a long name.

3. Make it yours. Hand an agent a screenshot or a few words ("warm, paper-like, big type"). The project's `AGENTS.md`
   tells it where the colours (`styles/tokens.css`), fonts, page, cards and parts are, which rules `npm test`
   checks, and how to compare its snapshots with your reference. By hand, start with the tokens.

4. Check and build:

   ```sh
   npm test            # card structure, class names, colours only from tokens, hover and motion rules
   npm run build       # dist/dashhaus-my-skin.js, one file with its CSS
   ```

5. Deploy. Copy `.env.example` to `.env` and fill in `HA_URL`, `HA_TOKEN` and `HA_WWW` as
   [Deploy a dashboard](../deploy/) describes, then:

   ```sh
   npm run deploy
   ```

   It builds, copies the file into Home Assistant, registers it, checks that Home Assistant serves it and creates
   **Home (My Skin)** the first time. Reload any open Home Assistant tab.

</Steps>

## What a skin starts with

Lights and room sensors, grouped by area, on a page with a header. `@dashhaus/core` also has hooks for climate,
covers, weather, alarm panels, humidifiers, switches and modes, sound machines and Owlet socks. `AGENTS.md` lists
the five places a new domain goes. The prebuilt bundle and your skin can live on the same Home Assistant: each
registers its own file and card.
